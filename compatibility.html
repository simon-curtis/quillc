Rust compatibility.

The goal is all of Rust.
Here’s where Quill stands.

Full compatibility means matching Rust’s language rules, diagnostics, Cargo workflows, and program behavior on Linux and Windows. Today, Quill builds a supported subset.

Language

Rust source parsing

Partial

Syn parses most stable syntax and some unstable syntax. Parsing a construct does not mean Quill can type-check or execute it.

Source notes ↗

Language

Functions and scalar arithmetic

Partial

Direct and recursive calls, selected i32/u64/usize operations, and supported returns. Division errors trap; Rust panic and overflow-check behavior are not fully matched.

Source notes ↗

Language

Control flow

Partial

Selected if/else, while, unlabeled loop, integer-range for loops, and unlabeled break/continue. Supported borrowed slices also have native iteration paths.

Source notes ↗

Language

Enums and match

Partial

Fieldless i32-represented enums and scalar patterns, including ranges, or-patterns, and simple identifier bindings. Guards, payload variants, and destructuring bindings are unsupported.

Source notes ↗

Language

if let

Partial

Nonbinding scalar and fieldless-enum patterns with literal or local-path scrutinees. Binding patterns are unsupported.

Source notes ↗

Language

Structs and inherent methods

Partial

Selected named fields, field reads, Self resolution, and fixture-specific record operations. General layout, privacy, generic substitution, and method dispatch remain incomplete.

Source notes ↗

Language

Tuples, arrays, and slices

Partial

Two-scalar tuple returns, selected fixed integer arrays, and borrowed integer or two-field tuple slices. General aggregate layouts and arbitrary slice signatures are not covered.

Source notes ↗

Language

Modules and imports

Partial

Inline and external modules, explicit imports and aliases, and public workspace function paths. Glob imports, reexports, and complete visibility rules are not implemented.

Source notes ↗

Language

Generics

Partial

Up to two type parameters in supported scalar and string-slice cases, recognized Copy/AsRef<str>/Add bounds, and deduplicated monomorphization. General bounds and inference are incomplete.

Checking

Type checking

Partial

Checks selected primitive expressions, calls, returns, fields, and library operations. Some unsupported expressions become unknown; this is not a Rust-compatible checker.

Not yet

No general trait solver. A small set of recognized bounds has dedicated support; arbitrary trait implementations are outside the native subset.

Not yet

Borrowed values in supported native paths do not establish borrow-checker compatibility. A complete Rust borrow checker remains work ahead.

Selected errors and source spans are implemented. Matching rustc diagnostics across ordinary Rust programs remains a compatibility goal.

Library & runtime

UTF-8 string literal helper calls

Available

The narrow native path passes a string literal to a one-argument &str helper and reads byte length. Empty strings, NULs, and multibyte UTF-8 are covered in documented runtime comparisons.

Source notes ↗

Library & runtime

Owned strings

Partial

Selected copying, formatting, parameters, and returns. Allocations remain mapped until process exit; full capacity, drop, and allocator behavior are missing.

Source notes ↗

Library & runtime

Vec and BTreeMap

Partial

Selected Vec<String> growth, Vec<Record> iteration, and BTreeMap<String, String> insertion paths. General collection layouts, APIs, and mutation are incomplete.

Source notes ↗

Library & runtime

Option, Result, and ?

Partial

Selected Option<()>/Option<i32>, Result<(), &str>, and same-width integer Result layouts, with supported status checks and propagation. Other payloads and indirect returns remain unsupported.

Source notes ↗

Library & runtime

Standard library, drop, and panic

Not yet

No general standard-library runtime or compatible drop/panic implementation. Dedicated supported operations do not establish std compatibility.

Source notes ↗

Cargo

Single binary with workspace libraries

Available

The subset command builds one default binary, at most one same-package library, and workspace-local ordinary library dependencies. It emits one combined executable.

Source notes ↗

Cargo

Features and cfg

Partial

Active Cargo features and supported target predicates are applied during source collection. Build-script cfg output and complete cfg processing are not implemented.

Source notes ↗

Cargo

External dependencies and build scripts

Not yet

The native subset rejects external dependencies and build scripts in the target dependency closure.

Source notes ↗

Cargo

Multiple binary targets

Not yet

The current native Cargo path accepts one default binary; general multi-target builds remain unsupported.

Source notes ↗

Cargo

Cargo artifacts and Rust ABI

Not yet

No Cargo-compatible rlib/metadata output. The backend uses a closed-program ABI for supported values, not full Rust binary compatibility.

Building Quill.

An independent Rust compiler, aiming for full compatibility on Linux and Windows and faster builds for the code you already write.

The compatibility goal

Quill aims to compile ordinary Rust crates with matching diagnostics and program behavior. That means the whole Rust language, its standard library, and the Cargo workflows developers rely on. Linux and Windows are the intended platforms.

This is the destination. The current implementation is an early compiler with a deliberately limited set of supported language features.

How the compiler is being built

Quill owns its code generator. Its current backend emits x86-64 machine code directly; it does not use LLVM or Cranelift. The object crate packages the generated bytes into an ELF object, and the system linker completes the executable.

The architecture uses cached queries to reuse work and a compiler-owned scheduler to run independent work in parallel. The performance target is at least three times the throughput of the pinned rustc on the same workload, without using more peak memory. This is the overall acceptance target. The first end-to-end fixture results are available below; they do not establish general Rust performance.

Current measurements

On the 30,992-line Catalog Flow fixture, median cold-build time is 282 ms for Quill and 2,653 ms for rustc through Cargo. A semantic edit takes 98 ms versus 300 ms. Cold-build peak process-tree RSS is 126.9 MiB versus 575.2 MiB. These are medians of three runs on an Intel i7-8700K, using release Quill and nightly 2026-08-23.

The executables produce matching output before and after the semantic edit. Quill emits one executable for the source graph; rustc also emits library artifacts. This is one synthetic fixture within Quill’s supported subset, not a general compatibility or performance result.

The stack

The compiler is written in Rust (2024 edition). Syn parses source syntax; Quill owns its intermediate representation and type checker. Rayon provides parallel execution behind the compiler scheduler. Cached queries and binary AST serialization reuse work across builds. The native backend uses the object crate for ELF object serialization and the system ld linker for executables.

What works today

The Rust compatibility index tracks language, checking, runtime, Cargo, and platform support with feature-specific restrictions.

The native target is Linux x86-64. Quill can compile supported standalone programs and has an early Cargo path for a package with one default binary, at most one library, and workspace-local ordinary library dependencies.

The supported subset includes selected forms of functions, integers, strings, structs, control flow, and output. General Rust compatibility, external Cargo dependencies, build scripts, multiple binary targets, and Windows output remain work ahead.

The repository README records the detailed supported forms and their restrictions as implementation progresses.

Try a supported Cargo package

From a local Quill checkout, use the project's pinned Rust toolchain and run:

cargo run -p quillc -- cargo-build-subset path/to/Cargo.toml -o ./program

Replace path/to/Cargo.toml with the manifest of a supported package. This command exercises the current Linux native path; it is not yet a replacement for a general Cargo build.

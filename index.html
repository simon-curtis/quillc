Before you try it

Your target
Linux x86-64 for supported programs. Windows output is still ahead.
Your dependencies
Workspace-local libraries have limited support. General crates.io and Git dependency support is incomplete.
Your workflow
Selected Cargo builds work. Cargo tests, doctests, and rustc-compatible library artifacts are not ready.

There is no reliable percentage for an arbitrary project yet. Its language features, dependencies, and build steps determine whether it will work.

How Quill is being built.

Quill generates machine code directly, caches work between builds, and runs independent tasks in parallel.

The goal is shorter builds with Rust’s language rules, diagnostics, and Cargo workflows intact. We compare the compiler with rustc, checking program output alongside build time and memory use.

From Rust to machine code.

Written in Rust, 2024 edition. Here’s how the current native path fits together.

ParseSyn CheckQuill HIR & type checker GenerateQuill x86-64 backend Linkobject & system ld

Read the source.

Syn parses Rust syntax. Quill retains source locations and module information, and caches parsed files so unchanged source can be reused.

Resolve and check.

Quill’s intermediate representation connects names, functions, and types. Its own checker validates the supported subset, with cached body checks reused when their inputs stay the same.

Emit native instructions.

Quill’s backend lowers supported functions into x86-64 machine code. It owns instruction selection, code emission, and relocations; LLVM and Cranelift are not dependencies.

Produce an executable.

The object crate packages generated code into ELF objects. The system linker, ld, combines them into a Linux executable.

Rayon provides the worker pool for independent compiler tasks.

Inspiration.

Go. Zig.Odin. Rust.

Quill draws on ideas from other compilers. Rust’s behavior is the reference; correctness and build measurements decide which ideas work here.

Go Small interfaces.
Keep package information compact. Explore loading function bodies only when they’re needed.
Zig Work that survives an edit.
Revisit what changed, reuse what didn’t. Keep all the checks that Rust requires.
Odin Independent work, in parallel.
Explore concurrent checking, with deterministic diagnostics and memory use under control.
Rust The compatibility reference.
Study rustc’s queries, intermediate representations, and crate metadata. Match its behavior.
